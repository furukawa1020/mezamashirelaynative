# めざましリレー

朝起きるのが苦手な人のための、仲間と一緒に起きる目覚ましアプリです。

## コンセプト

一人だと起きられないけど、誰かが待ってると思うと頑張れる。そんな感じのアプリ。

グループを作って、順番に起床ミッションをクリアしていく。前の人が起きないと次の人にバトンが渡らない仕組みなので、「自分が起きないとみんなに迷惑かけちゃう」っていうプレッシャーが良い感じに効きます。

## アカウントシステムについて

ある好きなサービスのアカウントシステムに影響を受けてます。

メールアドレスもパスワードも不要で、インストールしたら即使える完全匿名方式です。デバイスごとにUUIDを自動生成して、ローカルに保存してるだけ。バックエンドもないし、個人情報も一切収集してません。

ニックネームとアバターは任意で設定できるけど、設定しなくても「匿名ユーザー」として普通に使えます。最初のハードルを極限まで下げて、気に入ったら後からプロフィール設定すればいいよね、みたいな思想。

### セキュリティについて

完全匿名なので、なりすましとかは正直防げないです。今のところローカルだけで完結してるので、そこまで問題にはならないかなと。

将来的には：
- デバイスIDとUUIDの組み合わせで堅牢化
- サーバー側でトークン検証（グループ同期とか実装するなら）
- 悪用されそうな機能は段階的に制限（例：短時間に大量のグループ作成とか）

まあ、今はMVPなので、使いながら必要に応じて対策していく感じで。

## 開発メモ

### なんでFlutterなのか
クロスプラットフォームで作りたかったのと、UIがサクサク作れるから。React Nativeとか他の選択肢もあったけど、個人的にDartが書きやすかった。

### なんで匿名認証なのか
登録フォーム作るのめんどくさいし、ユーザーにとっても面倒。最初のハードルを下げて、使いながら愛着湧いたらアカウント作ってもらえばいいかなと。

あと個人情報管理したくない。GDPR対応とかめんどくさいし、プライバシー的にも匿名の方が安心。

### なんでBLEセンサーなのか
スマホのセンサーだけだと寝ながら操作できちゃうから、ベッドから離れた場所に置いた外部センサーと連携する必要があった。最初はWi-Fi経由とか考えたけど、BLEの方が消費電力少ないし、設定も楽。

XIAO ESP32C3 + MPU6050の組み合わせが安くて使いやすかった。


#### センサーの技術選択について

実はこれ、結構深い話がある。

**加速度センサーだけで結構いける説**

1軸の加速度センサーだけでも、「やったふり」の検知って意外とできるんじゃないかと思ってる。ドアの開け閉め、いつものスピード、開けたふり、そういうのの蓄積データ見れば、パターン認識で結構な精度出せそう。日本人のプライバシー意識的にも、カメラとかマイクより加速度センサーの方がまだ受け入れられやすいし。

**じゃあなんでやらないの？（コスト削減案の話）**

nRF系のSoC直載せ + 1軸加速度センサーだけなら、大量ロットで原価理論値300円ギリギリ耐えられる。技適も5000ロットで単価あたり60円だから、普通に原価的には成立する。最終単価1000円台で出せるかも。

でも実際はやらない。理由は：

- **環境個人差の影響がデカすぎる**: 同じ「ドア開ける」でも、人によって、環境によって波形が全然違う
- **電池寿命ポリシー**: 常時計測するとバッテリーがもたない
- **軸方向の設置問題**: ユーザーが適当に置いたら、加速度の向きバラバラ
- **波形の個人差**: 機械学習で吸収できるレベルを超えてる可能性
- **サポート返品地獄**: 「うまく動かない」って言われたら、そりゃそうなる
- **BLEとの通信思想と矛盾**: リアルタイムで送るのか、溜めて送るのか、思想が定まらない（これ意外とでかい）
- **大量ロットでのコスト構造**: 結局、最終1000円台で出そうと思うと原価300円じゃ無理。流通サポート不良率考えたら厳しい

**個人的に大きいと思ってる2つ**

1. **プライバシー配慮**: 加速度センサーでも、「行動を監視されてる」感は根強い。社会的な合意形成ができてない状態でやるのは、見えてる地雷。
2. **市場の成熟度**: ニーズが先行して、制度が後押しして、一番最後に技術がついてくる。今はまだニーズが顕在化してない。マス市場が求めてないと、ニッチなところで頑張るしかないけど、それってしんどい。

**だからMPU6050（6軸）を選んだ**

結局、「起きたかどうか」の検知に絞って、6軸センサー（加速度3軸 + ジャイロ3軸）を使う方が、精度も出るし、ユーザー体験も良い。コストは上がるけど、MVP（Minimum Viable Product）としてはこっちの方が正解。

1軸加速度だけでやるのは、技術的には面白い題材だけど、ビジネスとしては時期尚早かなと。もうちょい市場が成熟してから、また考えるかも。


#### もうちょいぼやく（センサーとコストの話）

**1軸加速度だけでも結構色々取れると思うんだよ**

あらゆるもののすべての開けしめ、いつものスピード、開けたふり、その蓄積。パターン認識で結構いけるんじゃないかと。加速度だけで行動証明できちゃうんじゃね？っていう。やったふり検知、結構いけるんじゃね？っていうのとか。

日本人のプライバシー意識にマッチするよな～。カメラやマイクと違って、加速度センサーなら「監視されてる感」が薄い。

**実際のビジネス感について考えてみた**

成立するのか？っていう話なんだけど：

- nRF系SoC直載せ + 1軸加速度だけ
- ロットで考えれば原価理論値300円ギリ耐える（やらないけど）
- 技適も、取りに行く前提で5000ロットでも単価あたり技適コスト60円
- 普通に原価的に耐えてる

**なぜじゃあやらないのか**

これ普通に「環境、個人差の影響がでかすぎる。コストに見合わない」で切り捨てれば終わりなんだけど、1回それは棚に上げて、それでもなぜか考えると非常に面白い題材だと個人的に思っている：

1. **電池寿命ポリシー** - 常時計測とかやってたら電池死ぬ
2. **軸方向の設置問題** - ユーザーが適当に置く前提だと、向きバラバラ問題が致命的
3. **波形の個人差** - 上3つを1回置いておいても、機械学習で吸収できるレベル超えてる
4. **サポート返品地獄** - そりゃそうなる。「動かないんですけど」って言われたら終わり
5. **BLEとの通信思想と矛盾** - これも意外とでかいし深掘りたい。リアルタイムで送るのか、溜めて送るのか、そもそも何を送るのか
6. **大量ロットでのコスト構造** - 最終で1000円台とかで出そうと思うと無理。原価300円じゃ流通サポート不良率考えたら絶対無理

**そんでなんやかんやが個人的に大きいと考えている2つ**

1. **プライバシー配慮** - やっぱ根強いし、社会的な合意形成できてない状態でやるのは見えてる地雷だからなぁ
2. **ニーズ先行で制度が後押しして一番最後に技術がついてくる** - で、通用するところとなるとニッチなところなんだけど、マス市場が求めていないと結局そういうのはしんどいしなぁ

**結論**

MPU6050（6軸）で起床検知に絞るのが、今のところ現実的。1軸加速度だけでやるのは技術的に面白いけど、ビジネスとしては時期尚早。もうちょい市場が成熟して、社会的合意形成ができてから、また考える。
